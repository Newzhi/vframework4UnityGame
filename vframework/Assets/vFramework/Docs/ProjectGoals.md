# 项目目标

本文档描述 **vFramework** 所服务的游戏产品目标与阶段性范围。框架的所有模块划分与优先级，均围绕「多人联机塔防」这一核心方向展开。

---

## 1. 产品定位

**多人联机塔防（Multiplayer Tower Defense）**

玩家在同一局战斗中协作或对抗，通过建造、升级防御塔抵御多波敌人进攻。框架需同时支撑：

- **单机/本地调试**：快速验证塔、路径、波次等玩法。
- **联机对战/协作**：房间匹配、状态同步、断线重连等网络能力。
- **持续迭代**：热更新资源与逻辑，便于平衡性调整与内容扩展。

---

## 2. 核心玩法目标（驱动框架需求）

| 玩法要素 | 对框架的要求 |
|----------|----------------|
| **大量单位同屏**（敌人、子弹、特效） | 对象池（`ObjPoolMgr`）、资源异步加载、性能友好的更新循环 |
| **波次与关卡流程** | 宏观流程 `GameFlow`（Boot / 战斗阶段）、场景切换（`SceneMgr`）；局内细粒度可用嵌套 FSM |
| **塔建造 / 升级 / 技能** | 逻辑层 MVC + Proxy，Model 存状态，Controller 处理输入与规则 |
| **多人状态一致** | 网络层收发协议，Proxy 解析并更新 Model，再通知 Controller / View |
| **UI 密集**（HUD、建造面板、结算） | `UIMgr`、View 与 Model 解耦，事件总线辅助刷新 |
| **配置驱动**（塔属性、波次表） | 配置表模块、资源热更、逻辑热更 |

---

## 3. 技术目标

### 3.1 框架层（vFramework）

- 提供清晰的三层结构：**基础架构层 → 全局系统层 → 业务逻辑层**。
- **BaseGameRoot**（生命周期 + IOC）与 **BaseAssetSys**（资源加载）为同级独立子系统，文档与排期分开维护。
- 全局 Manager 由 **GameRoot** 注册与 Tick，生命周期可控（不替代 Bundle Load API）。
- **资源域**（`BaseAssetSys` / `AssetLayer`）统一管理资源加载、场景、对象池。
- **第三方依赖下沉**：UniTask、Addressables 等仅在底层引用，上层通过接口访问。
- 业务层采用 **MVC + Proxy**：Proxy 处理网络数据更新 Model，Controller 协调玩法与 View。

### 3.2 联机相关

- 客户端-服务器（或 Host）架构，协议与传输在 **BaseNetwork / NetMgr** 层隔离。
- 塔防关键状态（波次、金币、塔位占用、实体 ID）需可序列化、可同步、可回放排查。
- 支持登录 → 大厅/匹配 → 加载战斗场景 → 局内 → 结算的完整链路。

### 3.3 工程与交付

- 程序集（`asmdef`）按层拆分，热更程序集 `HotUpdateLayer` 承载主要业务。
- 文档与代码目录一致，模块职责可单独测试与替换。
- 优先完成 **P0 骨架**（BaseGameRoot、EventBus、BaseAssetSys、网络分发、Logic Bootstrap），再扩展玩法。

---

## 4. 阶段性范围

### 当前阶段（框架搭建）

- [ ] **BaseGameRoot**：GameRoot 与模块注册中心（与资源加载独立）
- [ ] BaseEventSys 事件总线
- [ ] **BaseAssetSys**：`ResMgr` / `SceneMgr` / `ObjPoolMgr` 或现有 Bundle 加载 API（排期见 BaseAssetSys MainRoadmap）
- [ ] 网络底层与消息分发
- [ ] HotUpdateLayer：AppContext、Proxy / Controller 骨架
- [ ] 单机可跑的塔防原型场景（验证框架，非完整产品）

### 后续阶段（产品功能）

- 完整匹配与房间系统
- 权威服务器或帧同步方案选型与落地
- 塔、敌人、路径的完整配置管线
- 商业化与运营相关模块（按需）

---

## 5. 非目标（现阶段不做）

- 不做与塔防无关的通用 MMO 全套系统（公会、大世界等）除非后续明确立项。
- 不在 BaseFramework 中编写具体塔、敌人等业务逻辑。
- 不追求一次到位的大而全框架；先保证分层清晰、可扩展。

---

## 6. 成功标准

1. **分层清晰**：业务代码不直接引用 Addressables / Socket 等第三方 API。
2. **联机可扩展**：新增一条协议只需增加 Proxy + Model，不改 NetMgr 核心。
3. **塔防可验证**：能在联机或本地模式下完成「进房 → 战斗 → 波次推进 → 结算」最小闭环。
4. **团队可协作**：程序、策划、UI 可依据目录与文档并行开发。
