# 加载器设计说明（双层架构）

> 目录：`ABSystem_Beta/ResLoader/`  
> 相关：`AbstractAssets/AbstractResource.cs`、`BundleRuleConfig/Catalogue/`（清单）、[`Catalogue清单说明.md`](../Docs/Catalogue清单说明.md)

---

## 1. 总体思路

加载侧拆成 **两层**，职责分离：

| 层级 | 类 | 管什么 | 业务是否直接调用 |
|------|-----|--------|------------------|
| **Bundle 层** | `BundleManager` | `.bundle` 文件、包引用计数、**包依赖** | 一般不直接调用 |
| **Resource 层** | `BundleResLoader` | 包**内**具体资源、路径 API、缓存与释放 | **是**（业务入口） |

中间用 `AbstractResource` 做资源实例封装：Resource 层 Ref 归零时，再对 Bundle 层 `ReleaseBundle`。

```text
业务代码
    │  LoadByPath<T>("Assets/.../Panel.prefab")
    ▼
BundleResLoader          ← 查 Catalogue、缓存 AbstractResource、同步/异步
    ▼
AbstractResource         ← Resource 层 Ref；LoadAsset / Release
    ▼
BundleManager            ← AcquireBundleWithDependencies；依赖包顺序加载
    ▼
AssetBundle 文件         ← StreamingAssets / CDN 缓存目录等
```

---

## 2. Bundle 层：`BundleManager`

**职责**：只关心 **Bundle 容器**，不暴露给业务做 `LoadAsset`。

| 能力 | 说明 | 现状 |
|------|------|------|
| `Init(rootPath, reader)` | 设置 AB 根目录与 CatalogueReader | ✅ |
| `AcquireBundle(bundleName)` | 加载或命中缓存，Bundle Ref +1 | ✅ |
| `AcquireBundleWithDependencies(bundleName)` | 先 Acquire 清单依赖，再加载本体 | ✅ |
| `ReleaseBundle(bundleName)` | Ref -1，为 0 时 `Unload` | ✅ |
| `UnloadAll()` | 清空所有已加载包 | ✅ |

**设计要点**

- 同一 `bundleName` 全局一份 `AssetBundle` 实例，多资源共用，靠 Ref 决定何时卸载。
- 依赖解析属于 Bundle 层：例如加载 `ui.bundle` 前，先 `AcquireBundle` atlas / common 等（数据来自打包清单，见 Catalogue 文档）。
- 业务 **不应** 直接 `LoadFromFile` 或手动 `Unload`，避免与 Resource 层 Ref 不一致。

---

## 3. Resource 层：`BundleResLoader`

**职责**：业务侧加载入口，管理 **包内资源** 与 **逻辑路径**。

| 能力 | 说明 | 现状 |
|------|------|------|
| `Init(bundleRootPath)` | 初始化 Bundle 层 + 加载 Catalogue + 清空资源缓存 | ✅ |
| `Load<T>(bundleName, assetName)` | 同步加载，返回 `AbstractResource` | ✅ |
| `LoadByPath<T>(assetPath)` | 按工程路径加载（查 Catalogue entries） | ✅ |
| `LoadAsync` / 回调 / 预加载包 | 默认异步、竞态合并等 | 📋 TODO |
| `UnloadAll()` | 释放全部 Resource + Bundle | ✅ |

**设计要点**

- 对外 eventually：**只认资源路径**（`assetPath`），内部通过 `CatalogueReader` 解析为 `bundleName` + `assetName`。
- `resourceDic` 以 `bundleName/assetName`（或 `assetPath`）为 key 去重；同一资源多次 `Load` → Resource Ref 递增，不重复 IO。
- 使用完毕调用 `AbstractResource.Release()`；Ref 为 0 时触发 Bundle 层 Release。
- Prefab：`GetAsset` / `Instantiate()` 取原型；**实例 Destroy 与 Release 无关**（与 Unity 惯例一致）。

## 4. 两层引用计数如何联动

```text
Load 第 1 次 Panel.prefab
  → AbstractResource Ref = 1
  → BundleManager Acquire ui.bundle → Bundle Ref = 1（及依赖包 Ref）

Load 第 2 次同一 Panel（另一脚本）
  → AbstractResource Ref = 2
  → Bundle Ref 不再重复 LoadFromFile（已缓存）

Release × 2
  → AbstractResource Ref = 0 → UnLoad → ReleaseBundle(ui.bundle)
  → Bundle Ref = 0 → Unload(true)
```

Resource Ref 与 Bundle Ref **不必相等**（一个包内多个 asset、或多个 asset 共享同一包时，Bundle Ref 可能更高）。

---

## 5. 与清单（Catalogue）的关系

| 清单字段 | 使用者 | 用途 |
|----------|--------|------|
| `entries[]` | `BundleResLoader` / `CatalogueReader` | `assetPath` → `bundleName` + `assetName` |
| `bundles[]` | `BundleManager` | 加载某包前先 Acquire 依赖包 |

打包器写入清单；加载器 **只读** 运行时副本（如 `{bundleRoot}/Catalogue/AssetCatalog.json`）。

## 7. 业务侧需求对照（设计基线 §1–7）

完整路线图与 CDN 扩展见 **[Docs/业务API与CDN规划.md](../Docs/业务API与CDN规划.md)**。

| # | 需求 | 现状 |
|---|------|------|
| 1 同步加载 | ✅ `Load` / `LoadByPath` |
| 2 异步加载（默认） | ❌ `LoadAsync` 占位 |
| 3 加载+回调 | ❌ `LoadWithCallback` 占位 |
| 4 预加载包 | ❌ `PreLoad` 占位 |
| 5 卸载单个 | ✅ `AbstractResource.Release()` |
| 6 卸载全部 | ✅ `UnloadAll()` |
| 7 CDN 联网下载 | ❌ `BundleManager` 内 TODO(CDN)，仅本地 `LoadFromFile` |

## 8. CDN 与多根目录（扩展点）

当前 `Init(bundleRootPath)` 只支持 **单一本地根**（默认 StreamingAssets）。  
目标态需：

1. 对比远程/本地清单 `version`、`buildNumber`  
2. 下载缺失 bundle 到 `persistentDataPath`  
3. `AcquireBundle` 优先从缓存目录 `LoadFromFile`  

打包侧 **CdnHotUpdate** 产出在 `cdnOutputPath`，与运行时下载链路分离；详见 **业务API与CDN规划** §2。
