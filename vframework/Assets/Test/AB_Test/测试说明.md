## 1. 设计原则（保留原有思路）

| 原则 | 说明 |
|------|------|
| **场景驱动** | `TestABScene` + `LoadApiTestLogCollector` + 若干 `MonoBehaviour` Runner |
| **Case 协程** | 每个 Runner 按 Case 0→N 顺序执行，Case 间 `intervalSeconds` 间隔 |
| **结构化 JSON** | `LogOk` / `LogFail` → `Record(source, caseId, api, passed, detail)` |
| **并发** | 多 Runner 共享 Collector；全部 `NotifyRunnerComplete` 后写同一 JSON |
| **UnloadAll 独占** | 每套系仅一个 Runner 可 `TryClaimUnloadAll` |
| **不破坏基准** | 同步双 Runner **19/19**（`ConcurrentLoad_*`）保持独立套系，不与 Router/Stress 混跑 |

新套系继承 [`AbLoadTestRunnerBase.cs`](./AbLoadTestRunnerBase.cs)，旧脚本 `Myloadtest` / `MyLoadTest2` **不改结构**，避免回归基准失效。

## 3. 场景挂载与 Collector 配置

**同一时刻只启用一套**（除 §5 扩展并发外）。

| 套系 | 启用组件 | 禁用组件 | Collector |
|------|----------|----------|-----------|
| **A 同步** | `Myloadtest`, `MyLoadTest2` | Uni/Router/Stress | `expectedConcurrentRunners=2`, `sessionIdPrefix=ConcurrentLoad_`, `unloadAllRunnerSource=Myloadtest` |
| **B 异步** | `MyLoadUniTest`, `MyLoadUniTest2` | 其余 | `UniConcurrentLoad_`, `unloadAllRunnerSource=MyLoadUniTest` |
| **C Router** | `MyRouterTest` | 其余 | `expectedConcurrentRunners=1`, `sessionIdPrefix=RouterLoad_` |
| **D Stress** | `MyLoadStressTest` | 其余 | `expectedConcurrentRunners=1`, `sessionIdPrefix=StressLoad_`, `unloadAllRunnerSource=MyLoadStressTest` |

所有 Runner 的 `logCollector` 指向同一 `LoadApiTestLogCollector`。

## 4. 套系 C — Router Case 明细

| Case | API | 通过条件 |
|------|-----|----------|
| 0 | Catalogue | `EnsureReady`；记录 `buildMode` |
| 1 | Route RESOURCES | `RouteAssetSource` → `RESOURCES` |
| 2 | Load RESOURCES | `Load<TextAsset>("Resources/ResourceSystemDesignGuide")` |
| 3 | Route ABUNDLE | DeviceDebug → `ABUNDLE`；EditorTest → `EDITORRESOURCES` |
| 4 | Load ABUNDLE | `Load<Sprite>("Icon/3")` 成功并 Release |
| 5 | Route EDITORRESOURCES | Editor + `buildMode=EditorTest`；否则 **SKIP** |
| 6 | Route NETCDN | Fake `IBundlePathResolver` → `NETCDN`；Case 末恢复 Router |

**EditorTest Case 5 前置**：打包器选 **EditorTest** 打清单，或工程内 `AssetCatalog.json` 的 `buildMode` 为 `EditorTest`。

**Resources 探针**：使用工程已有 `Assets/Resources/ResourceSystemDesignGuide.md`（无需额外贴图）。

## 5. 套系 D — Stress 与后续三 Runner 并发

当前 `MyLoadStressTest` 独立运行。若要与 `Myloadtest` + `MyLoadTest2` **同时**压力测：

1. 三者同挂 `ABundleTestRunner`，全部 `runOnStart=true`
2. Collector：`expectedConcurrentRunners=3`
3. 修改 `Myloadtest`：`PeerRunnerSource` 改为等待 **两个** Peer（或抽成 `string[] peerRunnerSources`）
4. **仅 `Myloadtest` 或 `MyLoadStressTest` 之一** 设 `unloadAllRunnerSource`（避免双 UnloadAll）

后续可加 `MyLoadStressTest2.cs`（Instantiate/Destroy 循环），同样继承 `AbLoadTestRunnerBase`，按同样模式注册 Runner 名与 Case。

## 6. 如何写新 Runner（模板）

```csharp
public class MyCustomTest : AbLoadTestRunnerBase
{
    protected override string LogSource => "MyCustomTest";
    protected override int CaseCount => 3;

    protected override IEnumerator RunCase(int caseId)
    {
        switch (caseId)
        {
            case 0: /* LogOk / LogFail */ break;
            case 1: yield return SomeCoroutine(); break;
        }
        yield return null;
    }
}
```

约定：

- **LogOk / LogFail / LogSkip**：走基类，自动进 JSON
- **Load 成功**：尽量 `Release()`，Case 末或 `OnDestroy` 兜底
- **UnloadAll**：`logCollector.TryClaimUnloadAll(LogSource)` 通过后再调
- **sessionIdPrefix**：新套系用新前缀，归档写进 `集成测试归档.md`
